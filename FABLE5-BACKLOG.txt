Written 2026-07-02 by a Fable 5 session with full context of the codebase
(it had just walked every screen, retired Classic search, and shipped the
annotation hint). Owner has ~5 days of Fable 5 access. This file is the
menu: each item is scoped so ONE session can land it end-to-end.

HOW TO RUN A SESSION (the protocol that has worked)
  1. Session reads CLAUDE.md first (always), then this file.
  2. Pick ONE item (or one Tier-1 + one small Tier-2). Resist bundling.
  3. VERIFY CURRENT STATE before building — plans and counts in docs drift;
     read the code ([[verify-current-state-not-plan]]).
  4. Implement → preview-verify on the real corpus (import the owner's
     .votbak via adb if real data helps — proven workflow, see the
     2026-07-02 CLAUDE.md entries) → full gates (vitest + coverage +
     typecheck + lint --max-warnings 0 + smoke:ci) → CLAUDE.md handoff
     entry → commit → push → gradle assembleDebug + adb install -r if the
     owner's phone is connected.
  5. Mark the item DONE here with a one-liner.

HARD CONSTRAINTS (owner policies — never violate)
  • NO AI features, NO API keys, NO LLM anything. NO auth/login. NO new
    network egress (the app is self-contained + offline; only existing
    egress: Garden images from GitHub, external links opened OUT).
  • Do NOT touch the welcome splash (UX6 — owner veto).
  • Hidden Manna stays out of every public index/search/home tile.
  • Data faithfulness: never author content that isn't on the live site;
    corpus edits need CORPUS_VERSION bump + check_balance.py.
  • ≤800-line app.jsx canary; 428-global lint gate (regenerate via
    npm run lint when window-globals change); pre-commit rebuilds bundles
    from the working tree — one logical change per commit.

ALREADY REJECTED / ADJUDICATED — do NOT re-litigate
  • PF3 IntersectionObserver windowing (dropped: risks the load-bearing
    scroll-restore/annotation layer; content-visibility landed instead).
  • PERF1 cold-boot restructuring (won't-do: risk > gain, no budget users).
  • D3 global strictNullChecks; D4 NavContext; D8 wholesale sheet-hook
    dissolve; PF2 minify bundle-a (react UMD reads top-level `this`).
  • UX6 welcome splash changes.

[1] MY NOTES FULL-TEXT SEARCH  (gap found in the 2026-07-02 screen walk)
    Bookmarks, Links, and Highlights index screens all have a search box;

    Acceptance: typing "covenant" filters both tabs live; empty state for
    no matches; tests for the filter fn; visual parity with Bookmarks.
    Effort: S.  Files: NotesIndexScreen.jsx (+ small CSS reuse).

[2] EXPORT NOTES / NOTEBOOK AS TEXT (shareable study notes, zero egress)
    A "Share as text" action on a notebook (drilled header ⋯ or button)
    and on All Notes: compose a plain-text/markdown document (note anchors
    as quotes + bodies + source labels + dates), hand it to the existing
    share/save path (navigator.share / SAF text write — the journal
    recording save + export flows show the pattern). NO new formats in
    backup — this is a human-readable artifact, not a backup.
    Acceptance: a 3-note notebook exports a readable .md/.txt; verified on
    web preview; Android path compiles + emulator-verified if possible.
    Effort: M.  Files: NotesIndexScreen, a small utils/notes-export.js.

[3] "MY PROGRESS" DASHBOARD (all data already exists, pure UI)
    One screen unifying: Mark-as-Read percentages (per collection — the
    Settings rows already compute them), journal streak (JournalStats),
    counts of notes/highlights/bookmarks, most-annotated books/letters
    (AnnotationStore keys → group by book/letter, resolve titles the way
    noteSourceLabel does). Entry point: Library card or Home tile.
    Acceptance: renders offline from stores; zero new persistence;
    respects historyEnabled=false (hide history-derived rows).
    Effort: M.  Files: new screen + route + Library/Home entry.

[4] BACKUP FRESHNESS REMINDER (the only-backup story needs this)
    The app's ONLY backup is manual Export. Track lastExportAt (StateStore
    write in the export success path — both platforms), and at boot show
    the existing toast pattern if >30 days AND user data is non-trivial
    (>50 KB): "It's been a while since your last backup — Export from
    Settings." One-tap deep link to Settings; a settings toggle to disable
    the reminder. NO scheduling APIs, NO notifications — boot-check only.
    Acceptance: toast fires on a stale-stamped profile, not on fresh
    export; toggle silences; tests around the threshold fn.
    Effort: S-M.  Files: SettingsScreen export paths, use-app-shell-
    effects (or App boot effect), use-settings default.

[5] SMOKE SEARCH RESULT ASSERTION (deferred v1.1 item, now MiniSearch-only)
    tools/smoke.js "Search" step still only asserts the screen renders.
    Make it type a known query (e.g. "shepherd") and assert ≥1 result card
    + ≥1 <mark> — guarding the whole engine+UI path in CI forever.
    Watch: cold index build in headless CI (~10s budget; the corpus is
    already loaded by earlier smoke steps, and the golden suite proves the
    engine, so assert with a generous timeout).
    Acceptance: smoke:ci green locally + in CI with the new assertion.
    Effort: S.  Files: tools/smoke.js (+ SMOKE.md note).
